# How can learning programming make one a better designer?

*A reflection written for my first programming course, Interaction Design (2019). The
project it describes is [Rakeful](README.md).*

Programming seemed to be very hard and confusing at first, especially for someone who does not have any prior knowledge of the topic. There are many programming languages to begin with, front-end and back-end, for the web and for apps, and the confusion and complexity keep growing. As a designer, one can ask: should designers learn how to code? Further, can/should a designer ever be good at coding? Answering these questions was a very hard task before knowing what interaction designers really do, and what coding is all about. However, after building an understanding of design and code, one can form an opinion about the matter. In my case, I think that designers should learn how to code, but they do not have to be good at it. Getting to know the field of interaction design better, and the process of learning HTML, CSS and JavaScript shaped this view. That leads to the main question behind this paper; how learning programming can make one a better designer?

The first stage of learning programming was the hardest, everything seemed confusing and unconnected. The vocabulary was new, the skills we were learning seemed hard to process and we could not see where we were heading. This frustration is a natural phenomenon when learning a new skill, but the “should a designer code?” debate affects the way one handles the frustration. When we feel frustrated, we usually lean to the side of the debate that helps clearing out our frustration, and in this case “programming isn’t for designers to learn” appeals to us the most. This early judgment can ruin our learning experience, not only in programming, but in all aspects including design. Therefore, learning how to live comfortably with this frustration is a skill programming teaches us very well, because learning does not just happen, it needs a great deal of patience and determination. I noticed from my discussions with my classmates that everyone had their own unique way of transforming the frustration to an understanding. Finding one’s own way of learning is not an easy task, mine came from learning mathematics, which is very similar to programming, and that is to know how the system works in its core. In mathematics, there are a set of rules that everything is built on, if you know these rules you can expand and use your own ways and tactics to solve problems. Similarly, in programming we are talking to a machine, there are specific rules that we need to learn in order to be familiar with the language of the machine, then we can be creative and pass our messages in different ways.

When learning programming, we used a learning platform (Codecademy), a book (Eloquent JavaScript) and in-class tutorials. This method of learning was very helpful, repeating every topic we learned three times, made things easier to memorize and apply. Completing all assignments and be present in tutorials was immensely valuable in the learning process, giving one’s full energy and determination will definitely return great results. It wasn’t until the 4th week of the course that I started relating programming to design, it seemed very necessary to be familiar the terms and the way programming work in order to communicate with developers. The more we learned about programming, the more I realized how stupid computers and browsers can be. The way we talk with computers through code is similar to the way we talk with a kid or an unintelligent person. We need to define every variable, be very clear about the conditionals we are going to use for every situation, organize everything in arrays and object so they can be accessible and link every action to its outcome through the DOM. Learning that gives us a strong idea about what developers go through, it provides us with the necessary vocabulary that we need to use when talking to developers and it guides us to build realistic designs.

For our final project, my group and I were inspired by Zen gardens and we decided on making a raking sand-box with JavaScript. The project was a great opportunity for us to test what we learned during the course, though it was very challenging. We started by taking the code from the “particles” tutorial that we did in class, and we did some changes to stop the particles from moving and removed the lines between them. Then, we had to align the particles, which was very hard at first and took more time than we expected. We learned that even though some things may seem simple in theory, but when writing the code, it might turn out to be very hard. We used the skill we used to solve the chessboard challenge in eloquent JavaScript to align the particles, which was a loop inside a loop. After that, we had to make the particles responsive to mouse movement, which we could do using conditionals and made the particles to the sides of the cursor. The next step was to define the teeth of the rake, which was done using an array and link it to the mouse movement. We tried to make the movement of the cursor more fluid, we had to use a mathematical formula for that. That was when my strong interest in mathematics became handy, I tried to map out the angles of movement and how we could make them more fluid using trigonometry. However, I learned that writing that in code wasn’t an easy task, so we decided to add it later to the project instead. The last steps were adding the GUI, drawing the rake and making them responsive. That was a very easy task to do compared with what we have done up to that point, which made us feel the progress and improvement of our programming skills.
